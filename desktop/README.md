# Freedom Desktop: клиент для Windows и Linux

Настольное приложение Freedom (Electron): отдельное окно, уведомления, звонки, голосовые и видео, установка
одним файлом. Работает с сервером Freedom (contora.is-local.org) и совместимо со всеми остальными клиентами.

| Система | Установщик |
|---|---|
| Windows 10/11 (64 бита) | `Freedom-Setup-<версия>.exe` (NSIS) |
| Debian, Ubuntu, Mint и др. | `Freedom-<версия>-linux-<арх>.deb` |
| Fedora, RHEL, openSUSE и др. | `Freedom-<версия>-linux-<арх>.rpm` |

## Как пользователю установить
Скачайте файл со страницы входа веб-версии вашего сервера (блок «Приложение для компьютера»: там же SHA-256
для проверки) и установите:

    # Debian, Ubuntu, Mint
    sudo apt install ./Freedom-*.deb
    # Fedora, RHEL, Rocky, Alma
    sudo dnf install ./Freedom-*.rpm
    # openSUSE
    sudo zypper install --allow-unsigned-rpm ./Freedom-*.rpm

На Windows запустите `.exe` и следуйте мастеру (выбор папки, ярлыки на рабочем столе и в меню «Пуск»).
Установщик пока **не подписан** сертификатом издателя, поэтому SmartScreen покажет предупреждение: «Подробнее» →
«Выполнить в любом случае». Удаление: «Приложения и возможности» (Windows), `sudo apt remove freedom-chat` или
`sudo dnf remove freedom-chat` (Linux). Настройки не удаляются вместе с программой.

**Запуск:** приложение сразу открывает сервер **https://contora.is-local.org**. Адрес зашит в приложение, поля ввода
сервера нет, а соединение только по HTTPS. Если связи нет (сервер выключен, нет интернета, не проходит проверка
сертификата), показывается страница «Нет связи с сервером» с кнопкой «Повторить» (плюс повтор каждые 20 секунд).
Ошибки сертификата не обходятся. Другой сервер: измените `SERVER_ORIGIN` в `src/app-config.js` и пересоберите.

- **Данные:** `~/.config/Freedom/` (Linux), `%APPDATA%\Freedom\` (Windows): размер окна и данные
  сайта (ключи шифрования хранятся там же, в IndexedDB, как неизвлекаемые).

## Как собрать установщики
Нужны Node.js 20+ и **доступ в интернет** (скачиваются Electron и electron-builder). Сборка проверена только на
уровне логики (см. ниже): сами установщики в этой поставке не собирались.

    cd desktop
    npm install
    npm test                 # проверки без Electron
    npm run dist:linux       # dist/*.deb и dist/*.rpm (на Debian/Ubuntu: sudo apt install rpm)
    npm run dist:win         # dist/Freedom-Setup-*.exe (собирайте на Windows)
    npm run publish:local    # копирует dist/*.exe|deb|rpm в ../server/downloads

Рекомендуется собирать на «родных» системах: `.rpm` требует `rpmbuild`, а `.exe` на Linux требует Wine.
Проще всего GitHub Actions: `.github/workflows/desktop.yml` собирает Linux-пакеты и Windows-установщик, а по тегу
`desktop-v1.0.0` кладёт их в Release. После первого `npm install` закоммитьте `package-lock.json`.

После публикации кнопки «Скачать» на странице входа появятся сразу (сервер перечитывает папку `downloads/`).
Показывается по одному, самому свежему, файлу каждого типа. Другая папка: переменная `CHAT_DOWNLOADS`.
Новая версия: поменяйте `version` в `package.json`, пересоберите и опубликуйте (автообновления в клиенте нет:
пользователи ставят новый пакет поверх старого).

## Устройство и безопасность
- Окно загружает интерфейс **с сервера contora.is-local.org**, а не хранит его внутри. Поэтому клиент всегда совпадает с версией
  сервера, но и доверие такое же, как у веб-версии: скомпрометированный сервер мог бы отдать изменённый код
  (подробнее в `E2EE.md`, §8). Шифрование при этом выполняется на устройстве.
- Загруженная страница работает без доступа к Node.js (`sandbox`, `contextIsolation`), мост IPC доступен только
  странице выбора сервера, переходы за пределы сервера и новые окна открываются в системном браузере.
- Камера, микрофон и уведомления разрешены только этому серверу; `http://` не открывается ни в окне, ни во внешнем браузере.
- Один экземпляр приложения: повторный запуск выводит окно на передний план.

Не входит: автоматическая (без участия человека) загрузка и установка обновления, значок в трее, счётчик
непрочитанных на значке, подпись установщиков.

## Обновления
При каждом запуске (и по кнопке «Справка → Проверить обновления») приложение спрашивает сервер о версии
(`/api/ping`, `/api/downloads`) и сравнивает со своей (`app.getVersion()`, то есть `version` в `package.json`).
Если вышла более новая версия — необязательный диалог со ссылкой на скачивание с сервера; выбор «Позже»
запоминается в конфиге (`dismissedUpdateVersion`) и не повторяется для той же версии. Если версия ниже той,
что сервер ещё поддерживает (`MIN_CLIENT_VERSION_WINDOWS`/`_LINUX` на сервере, см. корневой `README.md`, §8) —
диалог обязательный и показывается при каждом запуске. Сбой сети при фоновой проверке не показывает ничего и
не мешает работе; при проверке по кнопке — понятная ошибка. Логика версий и сравнения — `src/update.js`
(проверена отдельно от Electron, `test/update.test.js`); реакция на неё в `main.js` — `test/main.test.js`.

## Что проверено
`npm test` (37 проверок) прогоняет настоящие `src/main.js` и `src/update.js` с подменённым модулем `electron`:
параметры безопасности окна, права, защиту IPC, невозможность подменить адрес сервера, отказ обходить ошибки
сертификата, обработку ошибок загрузки, переходы и внешние ссылки, скрипт публикации, а также проверку
обновлений — необязательное и обязательное обновление, отложенную версию, сбой сети, кнопку меню (все — реальным
прогоном кода, не только чтением). Тесты проверены «мутациями»: намеренная поломка (отключить sandbox, доверять
любому адресу, убрать проверку IPC, разрешить подавлять обязательное обновление) их роняет. Чего проверить нельзя
без Electron и сети: запуск самого Chromium, сборку `.deb`/`.rpm`/`.exe` и работу установщиков. Это нужно сделать
при первой сборке.
